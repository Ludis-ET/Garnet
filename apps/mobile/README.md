# Garnet mobile

Expo (SDK 57) + React Native 0.86 + TypeScript (strict) + Expo Router. **Phase 2 prototype.** Accounts, pairing, setup and settings can run on the local API (`EXPO_PUBLIC_API_AREAS`, `src/data/http/`); everything else is sample data, told who is really signed in by `src/data/http/mirror.ts`. Rules: [AGENTS.md](./AGENTS.md). Designs and page prompts: [docs/design](../../docs/design/README.md).

## Run it

**Windows, one click:** double-click [`apps/run-mobile.bat`](../run-mobile.bat). It installs dependencies and starts the local backend (Docker, migrations, the API; see [infra/README.md](../../infra/README.md)), then offers: an Android phone over USB with real accounts, pairing and setup on that backend, the browser preview or Expo Go (both on sample data), or backend only.

From the repository root:

```sh
pnpm install
pnpm --filter @garnet/mobile start      # then press "a" for Android or scan the QR code
pnpm --filter @garnet/mobile exec expo start --web   # browser preview
```

- **Android:** a development build is the reliable path: `pnpm --filter @garnet/mobile exec expo run:android` needs the Android SDK (installed on this machine) and an emulator or a USB device. No emulator (AVD) has been created yet.
- **Expo Go:** works only if your Expo Go version supports SDK 57. Store builds of Expo Go track the newest SDK, so a development build may be required.
- **iOS:** needs a Mac with Xcode, or EAS cloud builds plus a physical iPhone (U-01 decides the devices).

## Android test APK and home-screen widgets (P-73)

A standalone APK for your own Android phone, built on this PC (nothing is uploaded):

```sh
pnpm --filter @garnet/mobile apk                # → apps/mobile/android/app/build/outputs/apk/release/app-release.apk
pnpm --filter @garnet/mobile apk -- --install   # also installs it on a phone plugged in over USB
```

It needs the Android SDK and JDK 17 or newer (both on this machine); the first build downloads Gradle and the NDK and takes a while. The script makes the widget images from your pictures (`scripts/make-widget-art.py`, needs Python with Pillow), generates the git-ignored `android/` project, and builds a release APK for arm64 phones, signed with the debug key.

- **Windows notes** (all handled by the script; verified 2026-10-29 on this PC):
  - Windows' 260-character path limit breaks the native C++ build under a long checkout path, so the script mirrors the repo to `C:\gb` (or `GARNET_BUILD_DIR`), installs there with a flat (`hoisted`) `node_modules`, and builds there. The APK lands in `C:\gb\apps\mobile\android\app\build\outputs\apk\release\`.
  - The NDK fails to link when the Android SDK path has a space, so an SDK without one is preferred (`C:\Android\sdk` here, with NDK 27.1 and CMake 3.31.6). The SDK's default CMake 3.22 loops "Re-running CMake"; the newest installed CMake is used.
  - A user folder with a space also breaks the Hermes step; the local config plugin [plugins/withWindowsHermesc.js](plugins/withWindowsHermesc.js) works around it.
- **Install by hand:** copy the APK to the phone and open it (allow "Install unknown apps" for your file manager), or `adb install -r <path to app-release.apk>` with USB debugging on.
- **Widgets:** long-press the home screen › Widgets › Garnet. Six widgets: Garnet today, Two clocks, Thinking of you, Something waiting, Coming up and Far apart ([plan](../../docs/design/widgets-plan.md)). They show "Open Garnet to begin" until you sign in and pair in the app.
- **Your data stays on the phone:** the demo keeps its state in a private file, and the widgets read only a small snapshot with no words in it.
- **Keep it to your own two phones.** The APK contains your character images; rights and distribution are unresolved (U-10, U-26).

## Verified

- `pnpm --filter @garnet/mobile test`: all suites pass (tokens, Open When rules, mock repositories, figure data and copy rules, motion properties, image lookup and layout, auth and pairing rules, auth and pairing screens).
- `pnpm --filter @garnet/mobile typecheck` and ESLint (with React Hooks rules): clean.
- `expo export --platform android` produces a Hermes bundle, so Metro resolves the workspace and `@garnet/domain`.
- The web build renders every figure scene and mood in headless Chrome (software WebGL).
- **Not yet verified:** running on a device or emulator, frame rate on phones, and iOS.
